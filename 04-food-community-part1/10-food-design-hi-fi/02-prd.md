## 1. Executive Summary

서울 구로 주변에 거주하며 자동차를 보유한 가족·커플이 반복적인 일상에서 벗어나 색다른 외식 경험을 찾을 수 있도록, 동네 주민들이 직접 숨은 맛집을 등록하고 공유하는 커뮤니티 웹 서비스를 만든다. 프랜차이즈와 광고 위주의 기존 맛집 플랫폼과 달리, 실제 방문자가 사진·내용·위치를 직접 올리는 지역 밀착형 콘텐츠로 차별화한다.

## 2. Background & Context

- 기존 맛집 플랫폼(포털 지도, 배달앱, 리뷰 서비스)은 광고성 정보와 프랜차이즈 노출이 많아, "진짜 숨은 맛집"을 찾기 어렵다.
- 구로 주변 거주자는 서울 서남권·경기 서부(광명, 부천, 시흥 등)까지 차로 이동 가능한 생활권을 가지고 있어, 도보 상권보다 넓은 범위의 맛집 탐색 수요가 있다.
- 가족·커플 단위 사용자는 "주말에 어디 가지?"라는 반복적인 고민을 갖고 있으며, 신뢰할 수 있는 이웃의 추천을 원한다.
- 본 서비스는 글 등록 장벽을 최소화(사진 + 이름 + 내용 + 주소)하여 콘텐츠가 빠르게 쌓이는 구조를 목표로 한다.

## 3. Objectives & Success Metrics

**Goals** (성공의 모습):
1. 사용자가 방문한 숨은 맛집을 사진·내용·주소·지도와 함께 쉽게 등록할 수 있다.
2. 사용자가 목록·검색을 통해 원하는 맛집 정보를 빠르게 탐색할 수 있다.
3. 구글 로그인 기반으로 가입 마찰 없이 커뮤니티에 참여할 수 있다.

**Non-Goals** (명시적 범위 제외):
1. 예약·주문·결제 기능 — 정보 공유 커뮤니티에 집중하고 커머스는 다루지 않는다.
2. 댓글·좋아요·팔로우 등 소셜 기능 — MVP에서는 글 등록·탐색에 집중하고, 반응 기능은 이후 단계에서 검토한다.
3. 네이티브 모바일 앱 — 웹(모바일 반응형)으로 시작한다.
4. 구로 외 지역 확장 마케팅 — 초기에는 구로 생활권에 집중한다.

**Success Metrics**:
| Metric | Current | Target | Measurement |
|--------|---------|--------|-------------|
| 등록된 맛집 글 수 | 0 | 출시 후 3개월 내 100건 | DB 게시글 수 |

| 가입 → 첫 글 등록 전환율 | - | 30% 이상 | 가입자 대비 글 1건 이상 작성자 비율 |
| 검색 사용률 | - | 세션당 30% 이상 | 검색 이벤트 / 세션 |

## 4. Target Users & Segments

**주 타겟**: 서울 구로 주변(구로구 및 인접 생활권)에 거주하며 자동차를 보유한 가족 또는 커플

- **가족 세그먼트**: 주말 외식 장소를 반복적으로 고민하는 30~40대 부모. 아이와 함께 갈 수 있는 넓고 주차 편한 곳을 선호.
- **커플 세그먼트**: 데이트 코스로 색다른 장소를 찾는 20~30대 커플. 분위기·사진 찍기 좋은 곳을 선호.
- **공통 특성**: 자동차 이동이 가능하므로 도보 상권을 넘어 차로 20~30분 거리까지 탐색 범위가 넓다. "일상에서 벗어난 색다른 경험"이 핵심 동기.

## 6. Solution Overview

**화면 구성 (5개 페이지)**:

1. **로그인 페이지** — 구글 로그인 버튼 단일 진입점. OAuth 인증 후 목록 페이지로 리다이렉트.
2. **맛집 목록 페이지** (홈) — 무한스크롤 카드 목록 + 상단 검색창 + 우하단 플로팅 글쓰기 버튼.
3. **맛집 등록 페이지** — 사진 업로드, 이름/내용/주소 입력창, 주소 기반 지도 미리보기.
4. **맛집 상세 페이지** — 사진 → 이름 → 내용 → 주소 → 지도 순 배치. 작성자에게만 수정/삭제 노출.
5. **마이페이지** — 닉네임, 프로필 이미지, 내가 쓴 글 목록.

**핵심 설계 결정**:
- **인증**: 구글 OAuth 단일 로그인으로 가입 마찰 최소화. 최초 로그인 시 구글 프로필의 이름·이미지를 닉네임·프로필 이미지 초기값으로 사용.
- **지도**: 등록 시 입력한 주소를 지오코딩하여 좌표로 저장하고, 등록/상세 페이지에서 지도에 마커로 표시. (국내 주소 정확도를 위해 카카오맵 또는 네이버지도 API 우선 검토)
- **목록 성능**: 무한스크롤은 커서 기반 페이지네이션으로 구현하여 데이터 증가에 대비.
- **권한**: 글 수정/삭제는 작성자 본인만 가능. 열람은 로그인 사용자 기준(비로그인 열람 허용 여부는 Open Question).
- **반응형**: 모바일 우선 반응형 웹으로 설계 (외출 중 탐색 시나리오가 많음).

**데이터 모델 (개요)**:
- `User`: id, 구글 계정 식별자, 닉네임, 프로필 이미지 URL
- `Post`(맛집 글): id, 작성자 id, 이름, 내용, 주소, 좌표(위도/경도), 사진 URL 목록, 작성/수정 시각

## 8. Timeline & Phasing

**Phase 1 — MVP (P0 전체)**:
- 구글 로그인 → 목록(무한스크롤·검색·플로팅 버튼) → 등록(사진·입력·지도) → 상세(수정/삭제 포함) → 마이페이지(조회)
- 산출물: 5개 페이지가 동작하는 배포 가능한 웹 서비스

**Phase 2 — 편의 개선 (P1)**:
- 프로필 편집, 주소 자동완성, 사진 다중 업로드

**Phase 3 — 커뮤니티 확장 (P2)**:
- 좋아요·댓글, 위치 기반 필터, 주차 정보 등 자동차 이용자 특화 기능

**의존성**:
- 구글 OAuth 클라이언트 등록 (Phase 1 착수 전)
- 지도 API 키 발급 (등록 페이지 개발 전)
