## 1. Summary

이 문서는 20~30대 여성 1인 여행자를 위한 **안심 숙소·혼밥 식당 큐레이션 서비스 "혼행"(가칭)의 첫 출시 버전(Wave 1 MVP)** 요구사항을 정의한다. 30명 설문에서 확인한 "혼자여서 생기는 제약"(안전 불안, 혼밥 부담, 1인 숙소 정보 부재)을 큐레이션으로 해결하고, OTA 제휴 수수료로 수익을 검증한다. 범위는 레드팀(04)과 ICE 우선순위(05)를 거쳐 확정된 것으로, 원 전략(03)의 P0였던 유료 SOS는 이 버전에서 제외된다.

## 3. Background

**무엇에 관한 것인가.** 1인 여행자 30명 설문(2026-06-28)에서 페인의 공통 뿌리는 "여행"이 아니라 **"혼자"** 였다: 안전 불안(페인 강도 4.6/5), 혼밥 부담(5명), 1인 숙소의 비용·옵션 불리(숙소 관련 요구 합산 9회). 30명 전원이 인스타그램·유튜브·블로그·구글맵 같은 범용 채널을 조합해 쓰고 있었고, 1인 여행 전용 도구는 쓰지 않았다.

**왜 지금인가.**
- 설문 응답자의 가입 의향이 평균 4.0/5로 높고, 후속 인터뷰 동의자가 22명 확보되어 있다 — 검증 파이프라인이 살아있는 지금이 실행 적기다.
- "안전만 보장되면 더 자주 다니겠다"(R001)는 응답이 보여주듯, 이 시장은 억눌린 수요다 — 문제를 풀면 시장 자체가 커진다.
- 단, "전용 도구 공백" 판단은 아직 경쟁 스캔으로 확인되지 않았다(04 KA5). Wave 0에서 확인 전까지 이 배경 서술은 가설이다.

**이 PRD가 이전 문서와 다른 점.** 전략 원안(03)은 유료 SOS를 P0로 두었으나, 레드팀(04)이 "무료 대체재(카카오톡 위치공유, iPhone 나의 찾기)가 이미 존재하고 지불 가치가 미검증"임을 지적했고, 우선순위 재계산(05) 결과 첫 제품은 **숙소 큐레이션 + 혼밥 추천**으로 확정됐다.

## 4. Objective

**목표**: Beachhead 고객(안전 걱정 때문에 1인 여행 결정을 미루는 20~30대 여성)이 **숙소와 식당 결정을 우리 서비스에서 안심하고 내리게 한다.** 이것이 되면 ① 고객은 여행 준비 시간을 줄이고 더 자주 떠나며, ② 회사는 OTA 제휴 수수료라는 첫 수익과 "안심 큐레이션" 브랜드 자산을 얻고, ③ Wave 2(구독) 확장의 신뢰 기반이 생긴다.

**전략 정합성**: "혼자여서 못 하던 여행을, 혼자서도 안심하고 하게 만든다"는 가치 제안(03·06)의 첫 실체화이며, 커뮤니티·그룹 기능을 만들지 않는 안티 포지셔닝을 유지한다.

**Key Results (베타 시작 후 8주 기준)**

| # | Key Result | 측정 |
|---|---|---|
| KR1 | 방문자 중 큐레이션 리스트 저장률 **20% 이상** | 저장 이벤트 / 순방문자 |
| KR2 | 주간 "안심 결정" 수(숙소 예약 클릭 + 식당 저장) **4주 연속 주당 15% 이상 성장** | North Star 대시보드 |

| KR4 | 베타 사용자 중 **30% 이상**이 여행 후 설문에서 "다음 1인 여행에도 쓰겠다" 응답 | 여행 완료 후 인앱 설문 |

## 6. Value Proposition(s)

**해결하는 고객의 Job**: "혼자 가는 이번 여행에서, 안심하고 묵을 곳과 혼자 먹을 곳을 빨리 정하고 싶다."

- **Gain**: 흩어진 블로그·인스타를 뒤지는 시간 절약, "혼자 가도 괜찮은 곳"이라는 확신, 더 잦은 1인 여행.
- **Pain 제거**: 밤 시간 안전 걱정(여성 1인 후기 기반 선별), 혼밥 문전박대 불안(1인 좌석·환영 여부 사전 확인), 1인 여행자에게 불리한 숙소 옵션 탐색 비용.
- **경쟁 대비 우위**: 범용 여행 앱(트리플·마이리얼트립)과 검색 채널(인스타·블로그)은 정보량으로 승부하지만 "혼자 가도 되는가"라는 질문에는 답하지 않는다. 우리는 그 질문에만 답한다.

| 커뮤니티·소셜 | 있음 | 있음 | **0 (의도적 제거 — 타깃이 기피)** |

## 7. Solution

### 7.1 UX / 사용자 플로우

프로토타입은 디자인 착수 후 첨부. 핵심 플로우(웹 MVP):

```
[홈: 목적지 선택 (3곳)]
   → [안심 숙소 리스트]  → [숙소 상세: 여성 1인 후기 요약·안심 포인트] → [OTA 예약 링크(제휴)] ✚ 저장
   → [혼밥 식당 리스트]  → [식당 상세: 1인 좌석·환영 여부·1인 메뉴]   → 저장
   → [내 리스트(저장함)] → 여행 전 체크: 카카오톡 위치공유 안내 카드
   → [안심 패스 소개]    → 가격 → 결제 진입 (fake-door: "준비 중" + 알림 신청)
```

UX 원칙:
- **안심은 정보로 전달하고, 보증으로 표현하지 않는다.** "검증됨·보장·인증" 금지, "여성 1인 여행자 후기 기반 선별" 같은 사실 서술만 허용 (04 KA4).
- 커뮤니티·피드·댓글 요소 없음. 저장과 결정에만 집중.
- 공포 소구 금지 — "위험하니까"가 아니라 "확인했으니까"의 톤 (06 열린 질문).

### 7.2 Key Features

**F1. 안심 1인 숙소 큐레이션** (ICE 227, 1위)
- 목적지별로 "혼자 묵기 좋은 숙소" 리스트 제공. 선별 기준: 여성 1인 여행자 후기 비율·평점, 위치(역·중심가 도보), 프런트 운영 시간, 1인 요금.
- 숙소 상세에 **안심 포인트 요약** (예: "여성 1인 후기 24건 · 밤 11시 체크인 가능 · 역 도보 5분")과 근거 후기 발췌 표시.
- OTA 제휴 링크로 예약 연결 (자체 예약 없음). 제휴 클릭 이벤트 추적.
- 콘텐츠는 런칭 시 목적지 3곳 × 숙소 15곳 이상, 주 1회 갱신.

**F2. 혼밥 식당 추천** (ICE 137, 2위)
- 목적지별 식당 리스트. 필수 표기: **1인 좌석 유무(바·카운터석), 혼밥 환영 여부, 1인 주문 가능 메뉴·가격대**.
- 여행 스타일 필터(미식/간단히/야식) 제공. 저장 이벤트 추적.
- 콘텐츠는 목적지 3곳 × 식당 20곳 이상.

**F3. 위치 공유 안내 (무료 신뢰 장치)** — 과금 기능 아님
- 여행 전 체크 카드에서 카카오톡 위치공유·iPhone 나의 찾기 설정 방법을 안내하고 딥링크 제공.
- Kano Must-be 대응(05): 이것 때문에 결제하지 않지만, 없으면 "안심" 포지셔닝의 신뢰가 깨진다. 자체 SOS 개발은 하지 않는다.

**F4. 안심 패스 fake-door** (검증 장치, KR3)
- "안심 패스(여행 1건 단위)" 소개 → 가격 표시 → 결제 진입 시 "준비 중" 안내 + 알림 신청 수집.
- 05의 kill criterion 검증용: 결제 의사 액션 3% 미만이면 상품화하지 않는다.

**공통 계측**: 순방문·리스트 조회·저장·OTA 클릭·fake-door 진입·알림 신청. North Star("안심 결정" = OTA 클릭 + 식당 저장) 주간 대시보드.

### 7.3 Technology (참고)

- 웹 MVP (반응형) — 앱스토어 배포 없이 빠른 반복. 콘텐츠는 CMS/시트 기반으로 비개발자가 갱신 가능하게.
- OTA 어필리에이트 API 또는 링크 프로그램 (제휴 확보가 선행 — §7.4 A5).
- 후기 데이터는 초기에 수동 큐레이션. OTA 후기 자동 수집은 약관 확인 전 금지.

### 7.4 Assumptions — 믿고 있지만 증명 안 된 것

레드팀(04)의 Kill-Assumption을 그대로 승계한다. **A1~A4는 Wave 0 검증 게이트로, 통과 전 개발 착수 금지.**

| # | 가정 | 검증 (Wave 0, 이번 주) | Kill criterion |
|---|---|---|---|
| A1 | "안심" 정보에 대한 수요가 무료 대체재(카톡 등) 위에 실재한다 | 연락 가능 22명 재접촉 — Imp/Sat 실측 + 지불 의사 (안전 페인 5명 우선: R001·R010·R019·R023·R026) | 과반이 "지금 수단으로 충분" → 안심 포지셔닝 수위 하향 |
| A2 | 설문의 지불 선호가 실제 결제로 이어진다 | 가격 명시 fake-door A/B | 결제 의사 액션 3% 미만 → 수익 모델 재설계 |
| A3 | 1인 여행 전용 도구 시장은 공백이다 | 경쟁·실패 사례 데스크 리서치 (반나절) | 동일 컨셉 실패 전례가 같은 구조적 이유면 전략 재검토 |
| A4 | Beachhead와 Wave 2 세그먼트는 한 제품으로 묶인다 (교차 수요) | 재접촉 인터뷰에서 교차 니즈 확인 | 교차 수요 없으면 Wave 2 통합 로드맵 폐기 |
| A5 | OTA 제휴(수수료율 포함)를 확보할 수 있다 | 제휴 프로그램 조사 + 컨택 (Wave 0 병행) | 제휴 불가 시 수익 모델을 fake-door 결과 기반 유료 상품으로 전환 |
| A6 | 후기 기반 선별만으로 "안심" 가치가 전달된다 (검증 인프라 없이) | 베타에서 저장률·정성 피드백 | 저장률 10% 미만이면 선별 기준 재설계 |

## 8. Release

정확한 날짜 대신 상대 기간으로 계획한다. 각 단계는 이전 단계의 게이트 통과가 조건이다.

| 단계 | 기간 (상대) | 내용 | 게이트 |
|---|---|---|---|
| **Wave 0 — 검증 스프린트** | 1주 | A1~A5 검증 (개발 리소스 0) | 게이트 실패 시 본 PRD 해당 결정 무효, v2로 개정 |
| **Wave 1 빌드** | 6~8주 | 목적지 3곳 콘텐츠 구축 (선행) → 웹 MVP 개발 → F1·F2·F3·F4 | 콘텐츠 기준치(숙소 15·식당 20/목적지) 충족 |
