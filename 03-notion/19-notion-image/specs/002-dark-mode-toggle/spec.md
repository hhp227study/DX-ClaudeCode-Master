# Feature Specification: 다크모드 (Dark Mode)

**Feature Branch**: `002-dark-mode-toggle`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "다크모드 기능을 구현해줘. 사이드바에 토글 버튼을 놓고, 이걸 클릭하면 다크모드로 변경돼야해."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사이드바 토글로 다크모드 전환 (Priority: P1)

미니 노션 사용자가 사이드바에 있는 테마 토글 버튼을 클릭하면, 앱 전체 화면이 즉시 다크모드로 전환된다. 다크모드 상태에서 다시 클릭하면 라이트모드로 돌아온다.

**Why this priority**: 사용자가 직접 요청한 핵심 기능이다. 이 스토리 하나만 구현해도 "버튼을 눌러 다크모드로 바꾼다"는 목표가 달성되는 최소 기능 제품(MVP)이 된다.

**Independent Test**: 앱에 접속해 사이드바의 토글 버튼을 클릭하고, 화면 전체(사이드바, 글 목록, 편집 영역)가 어두운 색상으로 바뀌는지 눈으로 확인하는 것만으로 완결적으로 테스트할 수 있다.

**Acceptance Scenarios**:

1. **Given** 라이트모드로 앱을 보고 있는 사용자가, **When** 사이드바의 테마 토글 버튼을 클릭하면, **Then** 페이지 새로고침 없이 화면 전체가 즉시 다크모드로 전환된다.
2. **Given** 다크모드로 앱을 보고 있는 사용자가, **When** 테마 토글 버튼을 다시 클릭하면, **Then** 화면 전체가 즉시 라이트모드로 돌아온다.
3. **Given** 어느 모드이든, **When** 사용자가 사이드바를 보면, **Then** 토글 버튼에서 현재 어떤 모드인지 시각적으로 알 수 있다.

---

### User Story 2 - 선택한 테마 유지 (Priority: P2)

사용자가 다크모드를 선택한 뒤 페이지를 새로고침하거나 앱을 껐다가 다시 접속해도, 마지막에 선택한 테마가 그대로 유지된다.

**Why this priority**: 접속할 때마다 매번 다시 토글해야 한다면 기능의 실사용 가치가 크게 떨어진다. 다만 전환 자체(P1)가 먼저 동작해야 의미가 있으므로 P2로 둔다.

**Independent Test**: 다크모드로 전환한 뒤 브라우저를 새로고침하고, 이어서 브라우저를 완전히 닫았다 다시 열어 접속했을 때 두 경우 모두 다크모드로 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 다크모드를 선택한 사용자가, **When** 페이지를 새로고침하면, **Then** 다크모드가 그대로 유지된다.
2. **Given** 다크모드를 선택하고 브라우저를 종료한 사용자가, **When** 나중에 다시 접속하면, **Then** 다크모드로 앱이 표시된다.
3. **Given** 저장된 테마가 있는 사용자가, **When** 페이지가 처음 로드되는 순간에도, **Then** 반대 테마가 잠깐 번쩍이며 보이는 현상 없이 저장된 테마로 바로 표시된다.

---

### User Story 3 - 첫 방문 시 기기 설정 따르기 (Priority: P3)

한 번도 테마를 선택한 적 없는 사용자가 처음 접속하면, 사용 중인 기기(운영체제/브라우저)의 다크모드 설정을 따라 초기 테마가 정해진다.

**Why this priority**: 있으면 자연스러운 경험이지만, 없어도 기본 라이트모드로 동작하는 데 문제가 없다. P1·P2가 완성된 뒤 더하는 마무리 개선이다.

**Independent Test**: 테마를 선택한 기록이 없는 상태(저장 데이터 초기화)에서, 기기의 다크모드 설정을 켜고 접속하면 다크모드로, 끄고 접속하면 라이트모드로 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 테마 선택 기록이 없고 기기가 다크모드로 설정된 사용자가, **When** 앱에 처음 접속하면, **Then** 앱이 다크모드로 표시된다.
2. **Given** 기기 설정을 따라 다크모드로 표시된 사용자가, **When** 토글 버튼으로 라이트모드를 선택하면, **Then** 이후에는 기기 설정과 무관하게 사용자의 선택이 우선 적용된다.

---

### Edge Cases

- 사이드바가 없는 화면(예: 로그인 화면)에서도 저장된 테마가 적용되는가? (전환 버튼은 없어도 테마 자체는 일관되게 적용되어야 한다)
- 저장된 테마 정보를 읽을 수 없는 경우(저장소 차단·삭제 등)에는 어떻게 되는가? (오류 없이 기본 동작 — 첫 방문과 동일하게 처리)
- 같은 앱을 여러 탭에 열어 둔 상태에서 한 탭에서 테마를 바꾸면? (다른 탭은 최소한 새로고침 시점에 새 테마를 반영해야 하며, 실시간 동기화는 필수 아님)
- 다크모드에서 이미지·아이콘·강조 색상이 배경에 묻혀 보이지 않게 되는 요소는 없는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사이드바에 라이트/다크 테마 전환 토글 컨트롤이 항상 표시되어야 한다.
- **FR-002**: 토글 클릭 시 페이지 새로고침 없이 앱 전체 화면이 즉시 반대 테마로 전환되어야 한다.
- **FR-003**: 토글 컨트롤은 현재 적용 중인 모드를 시각적으로 나타내야 한다(예: 아이콘·상태 변화).
- **FR-004**: 사용자가 선택한 테마는 저장되어, 새로고침·재접속 후에도 유지되어야 한다.
- **FR-005**: 테마는 앱의 모든 화면(사이드바, 글 목록, 글 편집, 검색, 프로필, 로그인)에 일관되게 적용되어야 한다.
- **FR-006**: 저장된 테마 선택이 없는 첫 방문 시에는 기기의 다크모드 설정을 따라 초기 테마가 결정되어야 한다.
- **FR-007**: 다크모드에서도 모든 텍스트·아이콘·구분선·강조 요소가 충분한 대비로 읽을 수 있어야 한다.
- **FR-008**: 페이지가 로드될 때 저장된(또는 기기 설정에 따른) 테마가 처음부터 적용되어, 반대 테마가 잠깐 보이는 깜빡임이 없어야 한다.

### Key Entities

- **테마 환경설정 (Theme Preference)**: 사용자가 선택한 화면 모드(라이트 또는 다크). 사용 중인 브라우저(기기) 단위로 저장되며, 값이 없으면 "아직 선택하지 않음"으로 간주해 기기 설정을 따른다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 사이드바에서 클릭 한 번으로 1초 이내에 테마를 전환할 수 있다.
- **SC-002**: 테마 전환 시 화면의 모든 영역이 동시에 바뀌며, 이전 테마 색상이 남아 있는 영역이 0개이다.
- **SC-003**: 테마를 선택한 사용자가 재접속했을 때, 100%의 경우 마지막 선택 테마로 표시된다.
- **SC-004**: 다크모드에서 앱의 모든 화면을 육안 점검했을 때, 읽을 수 없거나 배경에 묻히는 텍스트·컨트롤이 0건이다.
- **SC-005**: 페이지 로드 시 반대 테마가 번쩍이는 현상이 육안으로 관찰되지 않는다.

## Assumptions

- 테마 선택은 로그인 계정이 아니라 브라우저(기기) 단위로 저장한다. 여러 기기 간 동기화(계정 저장)는 이번 범위에서 제외한다.
- 지원 테마는 라이트/다크 2종이다. "시스템 설정 따르기"를 별도 선택지로 두는 3단 토글은 범위에서 제외하되, 첫 방문 초기값으로만 기기 설정을 활용한다.
- 기존 라이트모드 디자인은 변경하지 않으며, 다크모드는 동일한 레이아웃에 색상만 어둡게 적용한다.
- 테마 전환 버튼은 사이드바에만 두고, 사이드바가 없는 화면(로그인 등)에는 버튼 없이 테마 적용만 한다.
- 여러 탭 간 실시간 테마 동기화는 필수 요구사항이 아니다.
