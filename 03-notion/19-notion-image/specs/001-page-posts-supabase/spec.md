# Feature Specification: 페이지 게시글 Supabase 저장 전환

**Feature Branch**: `001-page-posts-supabase`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "페이지 게시글 기능 구현할거야. 이미 기존에 로컬스토리지로 구현되있었는데, 내가 Supabase에 만든 page 테이블에 저장되도록 변경해줘. 내가 만든 DB 테이블 구조는 변경하면 안돼. 로그인된 유저만 등록 가능하고, 자신의 글만 조회 가능하고, 자신의 글만 삭제할 수 있어야돼."

## Clarifications

### Session 2026-07-16

- Q: 기존 브라우저 로컬스토리지에 저장돼 있던 글(예시 노트 포함)은 어떻게 처리하나? → A: 이관하지 않음 — 전환 후 각 계정은 빈 목록에서 시작
- Q: 글 작성·수정 내용은 언제 중앙 저장소에 저장되나? → A: 지금처럼 자동 저장 — 입력이 멈추면 잠시 후 자동 저장, 별도 저장 버튼 없음
- Q: 비로그인 방문자가 글 목록·상세 화면에 접근하면? → A: 로그인 화면으로 이동하고, 로그인 성공 후 원래 가려던 화면으로 복귀

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 계정에 게시글 저장 (Priority: P1)

로그인한 사용자가 새 게시글(페이지)을 작성하면 브라우저가 아닌 사용자 계정에 저장된다. 브라우저를 바꾸거나 다른 기기에서 같은 계정으로 로그인해도 작성한 글이 그대로 보이고, 제목·내용을 수정하면 수정 내용도 계정에 저장된다.

**Why this priority**: 이 기능의 핵심 가치. 저장 위치를 브라우저 로컬에서 계정 기반 중앙 저장소로 옮기는 것 자체가 이번 변경의 목적이며, 이것만 되어도 사용자는 어디서든 자기 글을 이어서 쓸 수 있다.

**Independent Test**: 계정 A로 로그인해 글을 작성한 뒤, 브라우저 데이터를 지우거나 다른 브라우저에서 다시 로그인했을 때 같은 글이 보이면 성공.

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자, **When** 새 게시글을 만들고 제목과 내용을 입력하면, **Then** 글이 사용자 계정에 저장되고 목록에 나타난다
2. **Given** 계정 A로 글을 작성한 상태, **When** 다른 브라우저(또는 로컬 데이터 삭제 후)에서 계정 A로 다시 로그인하면, **Then** 작성했던 글이 동일하게 목록과 상세에 표시된다
3. **Given** 본인이 작성한 글, **When** 제목이나 내용을 수정하면, **Then** 수정된 내용이 저장되어 재접속 후에도 유지된다
4. **Given** 로그인하지 않은 방문자, **When** 게시글 작성을 시도하면, **Then** 등록이 차단되고 로그인 안내를 받는다

---

### User Story 2 - 내 글만 조회 (Priority: P2)

로그인한 사용자는 자신이 작성한 게시글만 목록과 상세 화면에서 볼 수 있다. 다른 사용자가 작성한 글은 목록에 나타나지 않고, 주소로 직접 접근해도 볼 수 없다.

**Why this priority**: 개인 노트 성격의 서비스에서 프라이버시를 보장하는 필수 조건. 저장(P1)이 된 다음 바로 갖춰져야 하는 접근 통제다.

**Independent Test**: 계정 A와 계정 B로 각각 글을 작성한 뒤, 계정 B로 로그인해 계정 A의 글이 목록·직접 접근 어디에서도 보이지 않으면 성공.

**Acceptance Scenarios**:

1. **Given** 계정 A와 계정 B가 각각 글을 작성한 상태, **When** 계정 B로 로그인해 글 목록을 보면, **Then** 계정 B의 글만 표시된다
2. **Given** 계정 A의 글 주소(고유 식별자)를 알고 있는 계정 B, **When** 그 주소로 직접 접근하면, **Then** 글 내용이 노출되지 않는다
3. **Given** 로그인하지 않은 방문자, **When** 글 목록이나 상세에 접근하면, **Then** 어떤 글도 노출되지 않고 로그인 화면으로 이동하며, 로그인 성공 후 원래 가려던 화면으로 복귀한다

---

### User Story 3 - 내 글만 삭제 (Priority: P3)

사용자는 자신이 작성한 게시글을 삭제할 수 있으며, 다른 사람의 글은 삭제할 수 없다. 삭제한 글은 목록에서 즉시 사라지고 재접속 후에도 복구되지 않는다.

**Why this priority**: 데이터 관리의 마무리 단계. 저장(P1)과 조회 통제(P2)가 갖춰진 뒤 본인 데이터에 대한 정리 권한을 제공한다.

**Independent Test**: 본인 글을 삭제해 목록에서 사라지고 재접속 후에도 없으면 성공. 우회 경로로 타인 글 삭제를 시도했을 때 실패하면 성공.

**Acceptance Scenarios**:

1. **Given** 본인이 작성한 글, **When** 삭제를 실행하면, **Then** 글이 목록에서 즉시 사라지고 재접속 후에도 나타나지 않는다
2. **Given** 다른 사용자의 글, **When** 화면 우회 경로(직접 요청 등)로 삭제를 시도하면, **Then** 삭제가 거부되고 원본 글은 유지된다

---

### Edge Cases

- 로그인하지 않은 방문자가 게시글 화면에 접근하면: 로그인 화면으로 이동하고, 로그인 성공 후 원래 가려던 화면으로 복귀한다
- 글 저장 중 네트워크 오류가 발생하면: 사용자에게 저장 실패를 알기 쉽게 안내하고, 입력 중이던 내용이 화면에서 사라지지 않는다
- 작성 도중 로그인 세션이 만료되면: 저장이 거부되고 다시 로그인하도록 안내한다
- 이미 삭제된 글을 다시 삭제하거나 조회하려 하면: 오류 없이 "글이 없음" 상태로 처리된다
- 다른 사용자 글의 고유 식별자로 직접 접근하면: 존재하지 않는 글과 동일하게 처리되어 내용이 노출되지 않는다
- 접근 통제는 화면에서만이 아니라 데이터 저장소 수준에서도 강제되어, 화면을 우회한 직접 요청으로도 타인 글의 조회·삭제·수정이 불가능하다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 게시글 등록은 로그인된 사용자만 할 수 있다. 로그인하지 않은 방문자가 게시글 화면에 접근하거나 등록을 시도하면 로그인 화면으로 이동되고, 로그인 성공 후 원래 화면으로 복귀한다
- **FR-002**: 게시글은 브라우저 로컬 저장소가 아닌 사용자가 미리 만들어 둔 중앙 데이터 저장소(page 테이블)에 저장되며, 같은 계정이면 어떤 기기·브라우저에서도 동일한 글 목록을 볼 수 있다
- **FR-003**: 사용자는 자신이 작성한 게시글만 조회할 수 있다. 타인의 글은 목록에 나타나지 않으며, 고유 식별자로 직접 접근해도 노출되지 않는다
- **FR-004**: 사용자는 자신이 작성한 게시글만 삭제할 수 있다. 타인의 글에 대한 삭제 시도는 거부된다
- **FR-005**: 사용자는 자신이 작성한 게시글의 제목과 내용을 수정할 수 있으며, 타인의 글은 수정할 수 없다. 작성·수정 내용은 별도 저장 버튼 없이 입력이 멈추면 잠시 후 자동으로 저장된다
- **FR-006**: 미리 만들어 둔 page 테이블의 구조(항목 구성)는 변경하지 않는다 — 항목 추가·삭제·형식 변경 금지
- **FR-007**: 조회·등록·수정·삭제에 대한 접근 통제는 화면(클라이언트)뿐 아니라 데이터 저장소 수준에서도 강제되어, 화면을 우회한 직접 요청으로도 규칙을 벗어난 접근이 불가능하다
- **FR-008**: 저장·삭제가 실패하면 사용자에게 알기 쉬운 오류 안내를 보여주고, 화면의 글 목록 상태가 실제 저장 상태와 어긋나지 않도록 한다
- **FR-009**: 기존 브라우저 로컬 저장 방식(초기 예시 글 포함)은 게시글 저장 경로에서 제거되고 중앙 저장소로 완전히 대체된다

### Key Entities *(include if feature involves data)*

- **게시글(Page)**: 사용자가 작성하는 글. 고유 식별자, 제목, 내용, 작성 시각, 작성자(계정) 연결 정보를 가진다. 저장 항목 구성은 이미 만들어진 page 테이블을 그대로 따르며 변경하지 않는다. 테이블에 없는 기존 화면 속성(이모지, 수정 시각)은 저장 대상이 아니다
- **사용자(계정)**: 기존 Google 로그인으로 인증되는 계정. 각 게시글의 소유자이며, 소유자만 해당 글을 조회·수정·삭제할 수 있다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인한 사용자가 글을 작성한 뒤 다른 브라우저(또는 로컬 데이터 삭제 후)에서 같은 계정으로 로그인하면, 작성한 글이 100% 동일하게 표시된다
- **SC-002**: 서로 다른 두 계정으로 각각 글을 작성했을 때, 상대방의 글이 목록·검색·직접 접근 어디에서도 0건 노출된다
- **SC-003**: 로그인하지 않은 상태의 게시글 등록 시도는 100% 차단되고 로그인 안내가 표시된다
- **SC-004**: 본인 글 삭제 시 목록에서 즉시 사라지며 재접속 후에도 삭제 상태가 유지되고, 화면 우회 경로를 포함한 타인 글 삭제 시도는 100% 실패한다
- **SC-005**: 일반적인 네트워크 환경에서 글 작성·수정·삭제 결과가 3초 이내에 화면에 반영된다

## Assumptions

- 수정 권한은 명시되지 않았으나 조회·삭제와 동일한 원칙을 적용해 "본인 글만 수정 가능"으로 간주한다
- 로그인하지 않은 방문자는 게시글 기능(목록·상세·작성)을 사용할 수 없으며 기존 로그인 화면으로 이동된다(로그인 후 원래 화면으로 복귀). 인증은 이미 구현된 Google 로그인을 그대로 사용한다
- 기존에 브라우저 로컬 저장소에 남아 있는 글(초기 예시 글 포함)은 중앙 저장소로 이관하지 않는다. 전환 후 각 계정은 빈 목록에서 시작한다
- page 테이블이 제공하는 항목(고유 식별자, 제목, 내용, 작성 시각, 작성자 연결)만 저장에 사용한다. 테이블에 없는 이모지는 화면 표시용 기본값으로 처리하고, 수정 시각은 별도 저장 없이 작성 시각을 날짜 표시에 사용한다
- 프로필(이름) 관련 기존 저장 방식은 이번 변경 범위에 포함되지 않는다
