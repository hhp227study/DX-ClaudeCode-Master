## Clarifications

### Session 2026-07-16

- Q: 사이드바를 접었을 때 어떤 형태가 되어야 하나요? → A: 아이콘 레일 — 사이드바가 좁은 폭으로 줄어들고 아이콘만 표시된다
- Q: 접힌 아이콘 레일에는 어떤 항목을 표시할까요? → A: 주요 액션만 — 토글·검색·새 글·프로필 아이콘만 표시하고 글 목록은 숨긴다

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사이드바 접고 펼치기 (Priority: P1)

글을 읽거나 편집하는 사용자가 화면을 넓게 쓰고 싶을 때, 사이드바에 있는 토글 버튼을 클릭해 사이드바를 접는다. 사이드바는 아이콘만 남는 좁은 레일로 축소되고, 본문 영역이 그만큼 넓어진다. 다시 목록이나 메뉴가 필요해지면 레일의 토글 버튼을 클릭해 사이드바를 원래대로 펼친다.

**Why this priority**: 이 기능의 핵심 가치 그 자체다. 이 스토리 하나만 구현해도 사용자는 요청한 기능을 온전히 사용할 수 있다.

**Independent Test**: 앱에 로그인한 상태에서 토글 버튼을 한 번 클릭해 사이드바가 아이콘 레일로 접히는지, 다시 클릭해 펼쳐지는지 확인하는 것만으로 완결적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사이드바가 펼쳐진 상태, **When** 토글 버튼을 클릭하면, **Then** 사이드바가 아이콘만 남는 좁은 레일로 축소되고(텍스트 레이블·글 목록은 사라짐) 본문 영역이 확장된다
2. **Given** 사이드바가 접힌 상태, **When** 토글 버튼을 클릭하면, **Then** 사이드바가 원래 모습(브랜드, 검색, 새 글, 글 목록, 프로필)으로 다시 펼쳐지고 본문 영역이 원래 폭으로 돌아온다
3. **Given** 사이드바가 접힌 상태, **When** 화면을 보면, **Then** 접힌 레일 안에 사이드바를 다시 펼칠 수 있는 토글 버튼이 보이고 클릭할 수 있다

---

### User Story 2 - 접힌 상태에서도 주요 액션 사용 (Priority: P2)

사이드바를 접어둔 사용자도 검색, 새 글 작성, 프로필 이동 같은 주요 기능은 레일의 아이콘을 클릭해 바로 사용할 수 있다. 기능을 쓰기 위해 매번 사이드바를 펼칠 필요가 없다.

**Why this priority**: 접힌 상태의 실용성을 결정하는 요소다. 다만 토글 자체(P1)가 없으면 의미가 없으므로 P2다.

**Independent Test**: 사이드바를 접은 상태에서 검색·새 글·프로필 아이콘을 각각 클릭해 펼침 상태와 동일하게 동작하는지 확인하는 것으로 독립 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사이드바가 접힌 상태, **When** 레일의 검색 아이콘을 클릭하면, **Then** 펼침 상태와 동일하게 검색 화면이 열린다
2. **Given** 사이드바가 접힌 상태, **When** 레일의 새 글 아이콘을 클릭하면, **Then** 새 글이 생성되고 해당 글 화면으로 이동한다
3. **Given** 사이드바가 접힌 상태, **When** 레일의 프로필 아이콘을 클릭하면, **Then** 프로필 화면으로 이동한다
4. **Given** 사이드바가 접힌 상태, **When** 레일을 보면, **Then** 글 목록은 표시되지 않는다

---

### User Story 3 - 페이지 이동·재방문 시 상태 유지 (Priority: P3)

사이드바를 접은 사용자가 앱 안에서 다른 화면(글 상세, 프로필, 홈 등)으로 이동하거나 브라우저를 새로고침해도, 마지막으로 선택한 접힘/펼침 상태가 그대로 유지·복원된다.

**Why this priority**: 사용 편의를 높이는 보조 기능으로, 없어도 P1·P2만으로 기능은 성립한다.

**Independent Test**: 사이드바를 접은 뒤 다른 페이지로 이동하고 새로고침해, 두 경우 모두 접힌 상태가 유지되는지 확인하는 것으로 독립 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사이드바를 접은 상태, **When** 앱 내 다른 화면으로 이동하면, **Then** 사이드바는 접힌 상태를 유지한다
2. **Given** 사이드바를 접은 상태, **When** 페이지를 새로고침하면, **Then** 사이드바는 접힌 상태로 표시된다
3. **Given** 사이드바를 펼친 상태, **When** 화면 이동 또는 새로고침하면, **Then** 사이드바는 펼쳐진 상태를 유지한다

---

### Edge Cases

- 사이드바가 접힌 상태에서 검색 단축키(Cmd/Ctrl+K) 등 사이드바 외 경로로 제공되는 기능은 계속 동작해야 한다
- 토글 버튼을 빠르게 연속 클릭해도 상태가 꼬이지 않고 최종 클릭 기준의 상태로 정착해야 한다
- 접힘 상태 전환 중(애니메이션 진행 중)에 페이지를 이동해도 레이아웃이 깨지지 않아야 한다
- 저장된 상태 정보를 읽을 수 없는 환경(첫 방문 포함)에서는 기본값인 펼침 상태로 표시한다
- 접힌 레일에서 현재 보고 있는 글이 글 목록에 없어도(목록 숨김) 본문 화면은 정상 표시되어야 한다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사이드바에는 접기/펼치기를 전환하는 토글 버튼이 하나 있어야 한다
- **FR-002**: 사이드바가 펼쳐진 상태에서 토글 버튼을 클릭하면 사이드바가 아이콘 전용의 좁은 레일로 축소되고, 본문 영역이 줄어든 폭만큼 확장되어야 한다
- **FR-003**: 사이드바가 접힌 상태에서 토글 버튼을 클릭하면 사이드바가 다시 펼쳐지고, 본문 영역이 원래 폭으로 돌아와야 한다
- **FR-004**: 접힌 레일에는 토글·검색·새 글·프로필 아이콘만 표시하고, 글 목록과 텍스트 레이블은 표시하지 않는다
- **FR-005**: 접힌 레일의 각 아이콘(검색, 새 글, 프로필)은 펼침 상태의 해당 항목과 동일하게 동작해야 한다
- **FR-006**: 접힘/펼침 상태는 앱 내 화면 이동 간에 유지되어야 한다
- **FR-007**: 접힘/펼침 상태는 새로고침·재방문 후에도 복원되어야 하며, 저장된 상태가 없으면 펼침 상태가 기본값이어야 한다
- **FR-008**: 토글 버튼은 현재 상태에서 어떤 동작이 일어나는지 알 수 있는 시각적 단서(아이콘 방향, 레이블 또는 툴팁 등)를 제공해야 하며, 접힌 레일의 아이콘들도 마우스를 올리면 이름을 확인할 수 있어야 한다
- **FR-009**: 토글 버튼은 키보드로 초점을 잡아 조작할 수 있어야 하며, 보조기술이 버튼의 용도와 현재 상태를 인식할 수 있어야 한다

### Key Entities

- **사이드바 표시 상태**: 사용자별 화면 선호 값으로, "펼침" 또는 "접힘(아이콘 레일)" 두 가지 상태를 가진다. 화면 이동·재방문 간에 유지된다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 클릭 한 번으로 사이드바를 접거나 펼칠 수 있다 (각 방향 1클릭)
- **SC-002**: 사이드바를 접으면 본문 가로 폭이 눈에 띄게 넓어진다 (사이드바는 아이콘 레일 폭만 차지)
- **SC-003**: 접힌 상태에서도 검색·새 글·프로필 기능을 각각 클릭 한 번으로 실행할 수 있다
- **SC-004**: 접힘/펼침 전환은 시각적으로 즉각적(0.5초 이내)으로 완료된다
- **SC-005**: 접힘 상태는 앱 내 화면 이동과 새로고침에서 100% 유지·복원된다
- **SC-006**: 처음 보는 사용자도 안내 없이 토글 버튼을 찾아 접기/펼치기를 수행할 수 있다

## Assumptions

- 접힌 레일의 정확한 폭, 아이콘 크기, 전환 애니메이션 방식 등 시각 세부 사항은 기존 디자인 시스템에 맞춰 구현 단계에서 결정한다
- 상태 저장은 사용자의 현재 브라우저 기준이면 충분하며, 기기 간 동기화는 범위 밖이다
- 이 기능은 사이드바가 표시되는 모든 화면(홈, 글 상세, 프로필)에 동일하게 적용된다
- 모바일 전용 반응형 레이아웃 개편은 이 기능의 범위 밖이다
