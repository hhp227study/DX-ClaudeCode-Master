지금까지 만들어진 프로젝트의 메타 정보(구현 코드, 레퍼런스 디자인, PRD)를 근거로 DESIGN.md를 만들어줘.
이건 "새로 디자인"하는 작업이 아니라, 이미 코드 안에 흩어져 있는 디자인 결정을 하나도 빠뜨리지 않고 문서로 옮기는 작업이야. 요약하거나 의역하지 말고, 코드에 있는 값은 값 그대로(px, ms, hex, font-weight 등) 옮겨줘.

===

## 읽어야 할 소스 (전부 확인할 것)

- `02-prd.md` — 목적, 가치제안, 기능 범위
- `03-reference-design.png` — 시각 레퍼런스
- `app/globals.css` — 디자인 토큰(:root)과 전체 클래스
- `app/layout.jsx`, `app/page.jsx`, `app/login/page.jsx`, `app/profile/page.jsx`, `app/notes/[id]/*`
- `components/AppShell.jsx`, `components/NoteEditor.jsx`, `components/SearchModal.jsx`
- `package.json` (사용 스택 확인용)

## 원칙

1. **추정 금지, 누락 금지** — 코드에 없는 값은 만들어내지 말 것. 코드에 있는 값은 하나도 빠짐없이 옮길 것.
2. **정확한 수치 표기** — "파란색 계열" 같은 서술 대신 `--blue-500: #4076ff` 처럼 실제 변수명·값을 그대로 표로 정리할 것.
3. **불일치는 삭제하지 말고 기록** — 레퍼런스 이미지와 코드가 다르거나, 한쪽에만 있는 요소가 있으면 임의로 합치거나 빼지 말고 "확인 필요" 섹션에 그대로 남길 것.
4. **완료 후 자체 검증** — 작성이 끝나면 `globals.css`의 클래스 셀렉터 총 개수를 세고, 문서에 언급된 클래스 개수와 대조해서 몇 개 중 몇 개를 반영했는지 마지막에 보고할 것. 누락이 있으면 그 자리에서 채워 넣을 것.

## 작업 절차

1. `globals.css`의 `:root` 변수 전체를 카테고리별(뉴트럴 컬러 / 브랜드 컬러 / 시맨틱 컬러 / 타이포그래피 / radius·shadow·motion)로 표로 정리한다. 변수명, 값, 용도(어디에 쓰이는지) 컬럼 포함.
2. `globals.css`의 클래스 전체를 컴포넌트 단위로 그룹핑한다 (버튼, 사이드바/내비게이션, 세그먼트 컨트롤, 노트 리스트뷰, 노트 카드뷰, 3단 뷰, 상세 바 + 브레드크럼 + 더보기 메뉴, 에디터 + 슬래시 메뉴, 마이페이지 폼, 검색 모달, 빈 상태). 그룹마다 클래스명, 치수(width/height/padding 등), 상태(hover/active/on/disabled/placeholder/new 등), 어느 페이지·컴포넌트에서 쓰이는지 적는다.
3. `.jsx` 컴포넌트를 읽고 상태 전이·인터랙션 로직을 문서화한다: 키보드 단축키(Cmd/Ctrl+K 검색, 슬래시 메뉴 방향키/Enter/Tab/Escape), 포커스 이동, 슬래시 메뉴가 열리고 닫히는 조건, 낙관적 업데이트 여부 등.
4. 페이지별 화면 구성을 `03-reference-design.png`와 대조한다. 일치 여부를 확인하고, 이미지에만 있고 코드에 없는 요소(또는 반대)는 "확인 필요" 섹션에 별도로 남긴다.
5. `02-prd.md`의 목적·가치제안을 근거로 디자인 원칙 2~4개를 도출한다. 각 원칙 옆에 근거(어느 PRD 문장 또는 어느 코드 패턴에서 나왔는지)를 같이 적는다.

## DESIGN.md 목차 (이 순서로 작성)

1. 개요 — 프로덕트명, 목적, 기술 스택 요약
2. 디자인 원칙
3. 디자인 토큰 — 색상 / 타이포그래피 / 간격·반경 / 그림자 / 모션
4. 레이아웃 구조 — 앱 셸(사이드바 폭 등), 메인 콘텐츠 폭, 반응형 여부
5. 컴포넌트 명세 (절차 2에서 정리한 그룹별로 하나씩)
6. 페이지 화면 명세 — 로그인 / 업무 페이지(리스트·카드·3단 뷰) / 글 상세 / 마이페이지 / 검색 모달
7. 인터랙션 & 키보드 단축키
8. 접근성 메모 (포커스 스타일, placeholder 대비 등 코드에서 확인되는 것만)
9. 확인 필요 / 추정 사항 (레퍼런스 이미지 vs 코드 불일치 포함)
10. 반영 결과 — "N개 클래스 중 N개 반영 완료" 자체 검증 결과
